# Verified bugs found and fixed

| Defect | Cause | Fix | Regression test |
| --- | --- | --- | --- |
| Provider discovery could offer an already elapsed slot later on the current day. | The mock catalog generated all fixed daily times without comparing today's slot with the current local time. | Filter each candidate against the timezone-aware local clock before returning it. | `MockProviderTests.test_search_excludes_elapsed_slots_today` |
| A process restart after the provider committed a booking could leave the app in an executing state and risk creating a duplicate or reporting the wrong outcome. | The local process can lose the response after the provider has committed; the prior in-memory control flow alone cannot establish what happened. | Persist the idempotency key and execution journal, recover pending actions, query authoritative status, and only retry after status confirms `not_booked`. | `ApprovalTests.test_restart_after_provider_commit_verifies_without_duplicate`; `ApprovalTests.test_approval_is_bound_to_provider_slot_and_quote_and_timeout_is_verified` |
| Correcting or forgetting a preference could leave its old value in the active task and approval card. | Memory selection excluded the old memory, but already-built task intent and pending approval retained a copy. | Scrub memory-derived task fields, clear presented options, invalidate the old approval, and move the task back to gathering. | `MemoryContextTests.test_forgetting_or_correcting_memory_scrubs_live_task_and_invalidates_its_approval` |
| A completed approval button continued to say “Checking provider status…” after the server had returned an outcome. | The browser disabled and relabeled the button before the request but never updated it after a successful response. | Set a typed final label from the authoritative application result while keeping the control disabled against repeat submission. | `node --test tests/test_frontend_feedback.cjs`; verified again in the recorded booking flow. |
| Stopping the local server could close SQLite while an HTTP polling handler was still using the shared connection. | Request threads were daemonized and not drained by `server_close()` before runtime cleanup. | Use non-daemon request handlers and wait for them to finish before closing runtime state. | `ServerTests.test_server_close_waits_for_inflight_handlers` |

The first three regression cases were included in the actual offline evaluation run recorded in [EVALUATION.md](EVALUATION.md). The interface feedback regression has its own Node built-in test and is verified in the recorded UI flow.
